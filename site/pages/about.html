About AnyGBA

Why this exists

I grew up with the Game Boy Advance. In primary school, the games I couldn't afford I played on a family PC through VisualBoyAdvance: Pokémon, a cheat code scribbled in a notebook, a save state before every hard fight. Those evenings are a big part of why I write software today.

AnyGBA is my way of giving something back to that childhood. I want to bring those games back to life, make them run better than they ever did on that old PC (native code, sharp at 4K, instant saves), make up for what that kid couldn't have, and carry the feeling forward for the next person who opens their old cartridges. VBA kept these games alive for a generation; this project hopes to carry them a little further.

Mình làm AnyGBA vì tuổi thơ, vì tình yêu với GBA và VBA từ những ngày tiểu học: để hồi sinh, cải thiện, bù đắp và tiếp nối tuổi thơ ấy.

In English: "I make AnyGBA for my childhood, for the love of the GBA and VBA since primary school days: to revive, improve, make up for and carry on that childhood."

How it works

  1. Analyse. anygba-recomp decodes the ROM's ARM and Thumb code and follows branches and calls to find every function it can.
  2. Translate. Each function becomes C that operates on a CPU state and calls the runtime for memory and hardware access.
  3. Compile. Your C compiler builds the generated code and links it with libanygba, the runtime that provides the BIOS, video, audio, saves, input and timing on top of SDL 3.
  4. Feed back. Anything the analysis missed runs in a fallback interpreter and is logged, so the next build can make it native.

It is part of anyport, a set of native-port projects built on static recompilation and high-level emulation of the system's software. Design details: ARCHITECTURE.md.

Contribute

  • Test games you own and report what happens in an issue: title, stage reached, and any error. Never attach or link a ROM.
  • Homebrew authors: open-source GBA games make great test cases for the compatibility list.
  • Code: build from source as described in the README, run the tests with ctest, and open a pull request. Keep commits focused, with conventional commit messages.
